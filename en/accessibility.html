Accessibility Statement

Last updated: July 3, 2026 · Based on Web Content Accessibility Guidelines (WCAG) 2.1 Level AA

CS.SIGN And Products Co., Ltd. ("the Company", "we") is committed to making the website cssign.co.th accessible and usable for all users, including users with visual, hearing, mobility, or cognitive impairments. This statement explains our accessibility goals, what has already been implemented, known limitations, and how to report an issue.

1. Standard We Follow

Our goal is for this website to conform to the Web Content Accessibility Guidelines (WCAG) 2.1 Level AA, published by the W3C — the same standard referenced by Thai government agencies in their website regulations, and a standard widely required by government bodies, state enterprises, and multinational companies in their own procurement conditions.

2. Conformance Status

This website is currently "Partially Conformant" with WCAG 2.1 Level AA, meaning some content does not yet fully conform to the standard, as detailed under "Known Limitations" below. We are continuing to make improvements and will update this status as progress is made.

3. Supported Accessibility Features

  • Skip to content link: Every page has a hidden link that appears as the first focusable element when pressing Tab, letting keyboard and screen-reader users skip the navigation menu and jump straight to the main content.
  • Semantic HTML structure: We use <header>, <nav>, <main>, and <footer> tags together with a correctly ordered heading hierarchy, so screen readers can interpret the page structure accurately.
  • ARIA labels for assistive technology: Icon buttons such as the mobile menu, search field, and chat widget carry aria-label text describing their purpose, rather than a bare icon alone.
  • Image alt text: Supporting images, such as our logo and portfolio photos, include alt text describing the image content.
  • Full keyboard navigation: All menus, buttons, and links can be reached and operated using the keyboard alone, without a mouse.
  • Page language declared: Every page declares the correct lang attribute (th for Thai pages, en for English pages) so screen readers pronounce content correctly.
  • Color contrast: The website's primary color scheme (dark blue #0B5A96 on white/dark backgrounds) is designed for readable contrast on the main body text.
  • Responsive design and zoom support: Pages adapt to different screen sizes and support browser zoom without content overlapping or disappearing.

4. Known Limitations and Improvement Plan

While we aim for the broadest coverage possible, some parts of the website have known limitations that we are aware of and are planning to address, including:

  • Standards-related documents: If you need a standards-related document in an accessible format, please contact us using the details below and we will be glad to provide a suitable version.
  • Element-by-element contrast checks: We have not yet verified the color contrast of every individual element (for example, text over photographic backgrounds in parts of the portfolio page) with automated tooling to 100% completeness.
  • Third-party map and chat widgets: Elements embedded from external providers (such as QR codes or maps) may have a level of accessibility support that depends on that provider, which is outside our direct control.
  • Not yet reviewed by an external expert: Our current assessment relies primarily on internal review and automated tools (see the next section); it has not yet been reviewed by real users of assistive technology or by an accredited external auditor.

5. Technologies Used

This website is built with standard HTML, CSS, and JavaScript (no framework that would limit accessibility). Full functionality relies on these technologies rendering correctly; compatibility is best with actively maintained, up-to-date browsers and assistive technologies (such as the latest versions of Chrome, Edge, Safari, and Firefox, together with screen readers such as NVDA, JAWS, and VoiceOver).

6. How We Assess Accessibility

CS.SIGN assesses this website's accessibility using the following methods:

  • Self-evaluation by our development team, referencing WCAG 2.1 Level AA criteria
  • Keyboard-only navigation testing (without a mouse) on the main pages

7. Reporting Accessibility Issues

We welcome feedback if you encounter a barrier accessing any part of this website. Please let us know the URL of the page where you encountered the issue and the device/assistive technology you were using, so we can investigate and address it accurately.
